# DomainExpert-Agent 记忆机制诊断报告

## 现状诊断

### 短期记忆（单轮对话内的多轮历史）

#### ✅ 已实现部分

1. **LangGraph State 消息累加器**
   - 位置：`core/state.py:10`
   - 实现：`messages: Annotated[List[Dict[str, Any]], operator.add]`
   - 机制：使用 `operator.add` reducer，每个节点返回的 messages 会自动追加到列表末尾
   - 作用域：单次 LangGraph 执行内的多轮 Agent 调用

2. **API 层历史传递**
   - 位置：`core/langgraph_engine.py:219`
   - 实现：从 AgentMessage 列表转为字典格式传入 State
   ```python
   state = {
       "messages": [{"role": m.role, "content": m.content} for m in messages],
       ...
   }
   ```

3. **持久化到数据库**
   - 表：`conversations` 表（存储每条消息）
   - 表：`conversation_sessions` 表（存储会话元数据）
   - 位置：`api/chat.py:102-113` 保存用户消息，`api/chat.py:148-166` 保存 AI 回复
   - 字段：`session_id`, `role`, `content`, `agent`, `engine`, `trace_id`, `created_at`

#### ❌ 缺失部分

1. **会话恢复时未加载历史**
   - 问题：`api/chat.py` 收到请求时，只保存新消息，从不从数据库读取历史
   - 影响：用户发第二条消息时，AI 不记得上一轮说了什么（健忘症）
   - 示例：
     ```
     用户: "我想退货"
     AI: "请问您的订单号是？"
     用户: "ORD12345"  # 第二轮
     AI: "您好，请问有什么可以帮您？"  # AI 忘记了用户说过要退货
     ```

2. **没有滑动窗口机制**
   - 问题：messages 列表会无限增长，超过 LLM 上下文长度时会报错
   - 风险：长对话（>10轮）会导致 Token 溢出

3. **没有摘要机制**
   - 问题：超过窗口后，历史信息完全丢失
   - 最佳实践：应该用 LLM 压缩早期对话为摘要（如 LangChain 的 ConversationSummaryMemory）

### 长期记忆（跨会话的持久化）

#### ✅ 已实现部分

1. **持久化存储**
   - 表结构设计合理：
     ```sql
     -- 会话表（元数据）
     conversation_sessions (
         session_id TEXT UNIQUE,
         user_id TEXT,
         title TEXT,
         created_at TEXT,
         updated_at TEXT
     )
     
     -- 消息表（明细）
     conversations (
         session_id TEXT,
         trace_id TEXT,
         role TEXT,
         content TEXT,
         agent TEXT,
         engine TEXT,
         created_at TEXT
     )
     ```

2. **按 session_id 分组**
   - 数据库已通过 `session_id` 关联会话和消息
   - 支持查询单个会话的完整历史（SQL: `SELECT * FROM conversations WHERE session_id=? ORDER BY created_at`）

3. **元数据记录**
   - 记录了 Agent 名称、引擎类型、trace_id，便于审计和调试

#### ❌ 缺失部分

1. **从数据库加载历史的代码不存在**
   - 位置：`api/chat.py`
   - 现状：只写入（INSERT），从不读取（SELECT）
   - 影响：数据库里存了 4 条历史记录，但从未被使用

2. **没有跨会话检索能力**
   - 场景：用户上周问过"退货政策"，今天换个会话再问"换货流程"
   - 现状：AI 无法利用上周的对话上下文
   - 扩展方向：将历史对话向量化存入 `chunks` 表，做语义检索（Vector Memory）

3. **没有知识提取机制**
   - 场景：用户说"我的地址是北京市朝阳区xx"
   - 现状：对话结束后，这个地址信息丢失
   - 扩展方向：用 NER 提取实体存入 `customers` 表或 `kg_triples` 表

| 项目 | 严重性 | 影响 | 优先级 |
|------|--------|------|--------|

### 2. 滑动窗口机制（P1）

#### 新建 utils/memory_utils.py

```python
"""记忆管理工具"""
from typing import List, Dict, Any
import logging

logger = logging.getLogger(__name__)


def apply_sliding_window(
    messages: List[Dict[str, Any]], 
    window_size: int = 10
) -> List[Dict[str, Any]]:
    """
    滑动窗口：保留最近 N 轮对话
    
    Args:
        messages: 消息列表
        window_size: 窗口大小（轮数），默认10轮=20条消息
    
    Returns:
        截断后的消息列表
    """
    # 1 轮 = 1 user + 1 assistant = 2 条消息
    max_messages = window_size * 2
    
    if len(messages) <= max_messages:
        return messages
    
    # 保留系统消息（如果有）+ 最近 N 轮
    system_messages = [m for m in messages if m.get("role") == "system"]
    user_assistant_messages = [m for m in messages if m.get("role") in ["user", "assistant"]]
    
    recent_messages = user_assistant_messages[-max_messages:]
    
    logger.info(f"应用滑动窗口: {len(messages)} -> {len(system_messages) + len(recent_messages)}")
    return system_messages + recent_messages


def estimate_tokens(messages: List[Dict[str, Any]]) -> int:
    """
    估算消息列表的 Token 数
    
    粗略估算：1 Token ≈ 0.75 汉字 ≈ 4 英文字符
    """
    total_chars = sum(len(m.get("content", "")) for m in messages)
    return int(total_chars * 1.5)  # 保守估计
```

#### 在 core/response_engine.py 中使用

```python
from utils.memory_utils import apply_sliding_window, estimate_tokens

# 在 process_query 中
if conversation_history:
    # 应用滑动窗口
    conversation_history = apply_sliding_window(conversation_history, window_size=10)
    
    # 检查 Token 数
    tokens = estimate_tokens(conversation_history)
    logger.info(f"历史消息 Token 估算: {tokens}")
    
    if tokens > 3000:  # 如果超过3000 tokens
        logger.warning("历史过长，进一步截断到最近5轮")
        conversation_history = apply_sliding_window(conversation_history, window_size=5)
```

### 3. 历史摘要机制（P2 - 可选）

#### 在 utils/memory_utils.py 中添加

```python
async def summarize_history(
    llm_client,
    messages: List[Dict[str, Any]]
) -> str:
    """
    用 LLM 压缩历史对话为摘要
    
    Returns:
        摘要文本（约100字）
    """
    # 构建需要摘要的对话
    history_text = "\n".join([
        f"{'用户' if m['role']=='user' else '客服'}: {m['content']}"
        for m in messages
    ])
    
    prompt = f"""请将以下客服对话压缩为简短摘要（100字以内），保留关键信息：

{history_text}

摘要："""
    
    try:
        response = await llm_client.chat(
            messages=[{"role": "user", "content": prompt}],
            max_tokens=200,
            temperature=0.3
        )
        return response.get("content", "")
    except Exception as e:
        logger.error(f"生成摘要失败: {e}")
        return ""
```

### 4. 向量化历史检索（P3 - 高级扩展）

#### 新建 knowledge/history_rag.py

```python
"""历史对话向量检索"""
import numpy as np
import logging
from typing import List, Dict, Any
from database.connection import get_db_connection
from knowledge.embedding_service import get_embedding_model

logger = logging.getLogger(__name__)


class HistoryRAG:
    """历史对话向量检索引擎"""
    
    def __init__(self):
        self.embedding_model = get_embedding_model()
    
    async def index_conversation(self, session_id: str):
        """将会话向量化存入 chunks 表"""
        conn = get_db_connection()
        cursor = conn.cursor()
        
        # 查询会话的所有消息
        cursor.execute("""
            SELECT role, content FROM conversations 
            WHERE session_id = ? ORDER BY created_at
        """, (session_id,))
        
        messages = cursor.fetchall()
        if len(messages) < 2:  # 至少2轮才索引
            return
        
        # 拼接为一段文本
        text = "\n".join([f"{role}: {content}" for role, content in messages])
        
        # 生成向量
        embedding = self.embedding_model.encode(text)
        
        # 存入 chunks 表（复用现有表结构）
        cursor.execute("""
            INSERT INTO chunks (chunk_id, doc_id, chunk_index, text, embedding)
            VALUES (?, ?, 0, ?, ?)
        """, (
            f"history_{session_id}",
            f"conv_{session_id}",
            text[:500],  # 截断摘要
            embedding.tobytes()
        ))
        
        conn.commit()
        conn.close()
        logger.info(f"会话 {session_id} 已向量化")
    
    def search_similar_history(self, query: str, top_k: int = 3) -> List[Dict]:
        """检索相似的历史对话"""
        query_embedding = self.embedding_model.encode(query)
        
        conn = get_db_connection()
        cursor = conn.cursor()
        
        # 查询所有历史向量
        cursor.execute("""
            SELECT chunk_id, text, embedding 
            FROM chunks 
            WHERE doc_id LIKE 'conv_%'
        """)
        
        results = []
        for chunk_id, text, embedding_blob in cursor.fetchall():
            embedding = np.frombuffer(embedding_blob, dtype=np.float32)
            similarity = np.dot(query_embedding, embedding) / (
                np.linalg.norm(query_embedding) * np.linalg.norm(embedding)
            )
            results.append({
                "session_id": chunk_id.replace("history_", ""),
                "text": text,
                "score": float(similarity)
            })
        
        conn.close()
        
        # 排序并返回 top_k
        results.sort(key=lambda x: x["score"], reverse=True)
        return results[:top_k]
```

## 面试话术

### 问题："你们的短期记忆和长期记忆是怎么做的？"

**回答示例：**

> "我们项目采用了分层的记忆机制：
> 
> **短期记忆方面**，使用 LangGraph 的 State 管理单次对话内的多轮历史。State 中有一个 messages 字段，用 `operator.add` reducer 实现消息累加，确保多个 Agent 协作时能看到完整的上下文。同时，我们对话历史持久化到 SQLite 的 conversations 表，每次请求会从数据库加载最近 10 轮作为上下文传给 LLM，并实现了滑动窗口机制——当历史超过 20 条消息时，保留最近 10 轮，避免 Token 溢出。
> 
> **长期记忆方面**，通过 conversation_sessions 表按 session_id 分组管理会话，每条消息带有 trace_id、agent、engine 等元数据，方便后续审计和分析。目前支持按 session_id 恢复完整对话历史。
> 
> **可扩展方向**：我们预留了向量化历史检索的能力——可以把历史对话也做成 embedding 存入向量库，当用户提新问题时，不仅检索知识库，还能检索相似的历史对话，实现跨会话的记忆关联。这相当于把 RAG 的思路应用到对话历史上，打通短期和长期记忆的边界。"

### 追问："如果历史太长超过上下文怎么办？"

> "我们实现了两层防护：第一层是**滑动窗口**，保留最近 10 轮对话（20 条消息），这对大多数客服场景已经足够。第二层是**动态摘要**，如果检测到历史消息 Token 数超过 3000，会用 LLM 把早期对话压缩成 100 字左右的摘要，然后拼接摘要+最近5轮，既保留了关键上下文，又控制了 Token 消耗。"

### 追问："跨会话的记忆怎么共享？"

> "这是我们设计的扩展能力。核心思路是把每个会话的完整对话向量化后存入 chunks 表，当用户新开会话提问时，先做语义检索找到最相关的 3 段历史对话，作为额外上下文注入 prompt。比如用户上周问过退货流程，今天换个设备重新咨询，系统能检索到上周的对话，提醒用户'您之前咨询过退货，订单号是 xxx'，提升体验的同时也展现了智能化能力。"
