## 关键发现

### ⚠️ **正例和负例分数有重叠**

```
正例最低分: 0.5115
负例最高分: 0.5483
分数间隙:  -0.0368 (负值 = 有重叠)
```

**重叠区间**: [0.5115, 0.5483]

**影响**: 
- 无法用一条阈值线完美分离正例和负例
- 任何阈值都会产生误杀（正例被拦）或误报（负例放行）
- 需要在召回率和精确度之间权衡

---

### 分数重叠的原因

1. **正例中有边缘案例**:
   - 某些问题虽然有答案，但匹配度不高
   - 例如"有什么卖点"匹配"产品信息"chunk，分数0.5115

2. **负例中有相似词汇**:
   - "支持RGB灯光调节吗" 中的"灯光"匹配竞品标题"发光"
   - 分数0.5483，比部分正例还高

## 阈值实施建议

### 方案 A: 单阈值 + 置信度标记（推荐）

**阈值**: 0.53

**返回策略**:
```python
if top1_score >= 0.53:
    return {
        "status": "found",
        "confidence": "high" if top1_score >= 0.60 else "medium",
        "answer": top1_chunk
    }
else:
    return {
        "status": "not_found",
        "message": "抱歉，我没有找到相关信息，建议您..."
    }
```

**优点**:
- 简单清晰
- 93% 正例召回 + 93% 负例拦截
- 置信度标记帮助用户判断

---

### 方案 B: 双阈值 + 灰度区

**高置信阈值**: 0.60
**低置信阈值**: 0.53

**返回策略**:
```python
if top1_score >= 0.60:
    return {"status": "found", "confidence": "high", "answer": top1_chunk}
elif top1_score >= 0.53:
    return {"status": "found", "confidence": "low", 
            "answer": top1_chunk, 
            "warning": "该答案可能不完全准确，仅供参考"}
else:
    return {"status": "not_found"}
```

**优点**:
- 更细粒度
- 灰度区提醒用户答案可能不准确

## 总结

### 核心发现

1. ✅ **正例表现依然优秀**
   - Recall@5: 100%
   - MRR: 0.8667
   - 平均排名: 1.27

2. ⚠️ **负例暴露问题**
   - 检索系统会给"没答案"的问题返回0.50~0.55的分数

4. ⚠️ **无法完美分离**
   - 分数重叠区间: [0.5115, 0.5483]
   - 需要在召回和精确度之间权衡
